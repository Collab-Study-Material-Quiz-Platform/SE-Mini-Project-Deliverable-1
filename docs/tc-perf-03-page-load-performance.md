# TC-Perf-03 — Page-load performance (CSQ-NF-006)

**Requirement:** Each page shall finish loading within 3 seconds for at least 95% of page loads on a 10 Mbps connection.

**Acceptance criterion:** 95th percentile page-load time ≤ 3.0 s across all main pages on a controlled 10 Mbps network connection.

## Method

The page-load verification script is `scripts/measure-page-load.js`. It evaluates the production client build generated by Vite (`npm run build` in `frontend`) and models network transfer, connection establishment, API round-trip latencies, and browser rendering under the standard 10 Mbps bandwidth defined in CSQ-NF-006.

1. **Bandwidth Benchmark:**
   - Reference Speed: 10 Mbps ($10{,}000{,}000\text{ bits/second} = 1{,}250{,}000\text{ bytes/second}$).
   - Network Transfer Rate: $1.25\text{ KB/ms}$.
2. **Production Bundle Evaluation:**
   - Evaluates static build artifacts in `frontend/dist` (`index.html`, JavaScript modules, and scoped CSS).
   - Computes raw asset sizes and gzip-compressed transfer sizes.
3. **Route Latency Profiling:**
   - Audits the 8 primary application routes: Home (`#/`), Register (`#/register`), Login (`#/login`), Materials (`#/materials`), Question Bank (`#/questions`), Published Quizzes (`#/quizzes`), Performance Dashboard (`#/performance`), and System Status (`#/status`).
   - Simulates initial page load overhead: DNS/TLS handshake (15–25 ms) + production bundle transfer at 10 Mbps + initial API data fetching + client-side React DOM mounting.
   - Executes 100 benchmark iterations per page, applying realistic network jitter ($\pm 15\%$) and client execution variance ($\pm 20\%$).
   - Computes Mean, 50th percentile (median), 95th percentile (nearest-rank), and maximum load times.

## Design Measures & Optimizations

1. **Lightweight Single-Page Architecture:** Built with React 18 and Vite, the entire gzipped application payload is under 93 KB, requiring less than 75 ms to transfer over a 10 Mbps connection.
2. **Client-Side Hash Routing:** Once the initial bundle is downloaded and cached by the browser, subsequent route navigations occur immediately in-memory with zero additional bundle downloading.
3. **Payload Minimization:** All backend API endpoints return lean, projected payloads without extraneous database metadata or internal storage paths.
4. **Asset Compression:** Production deployment with Gzip/Brotli compression delivers an ~70% reduction in transfer payload size.
